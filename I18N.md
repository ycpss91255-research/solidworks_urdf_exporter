# Interface languages

The add-in reads `ISldWorks.GetCurrentLanguage()` when it connects, and each
export form reads it when created. `chinese` selects Traditional Chinese
(`zh-TW`). English, unsupported languages (including `chinese-simplified`), a
missing application, and COM language-query failures use English. The host's
numeric culture and UI culture are never changed.

Main part/assembly form captions, dynamic joint-unit labels, PropertyManager
captions/tooltips, menu captions, name-validation messages and the package
destination message use resources. CAD names, URDF identifiers, joint-type
tokens, coordinate-system choices and numeric fields remain unchanged.
Technical exception details and diagnostic logs retain their original text.

Resources live in `SW2URDF/UI/Strings.resx` and `Strings.zh-TW.resx`.
Keys are lowercase English captions because ResGen treats keys differing only
by case as duplicates. English display preserves the caller's capitalization.
Unknown keys fall back to the original string. Adding a language requires its
resource file, an explicit native-language mapping, project/installer entries,
and coverage in the tests.

Deploy `zh-TW/SW2URDF.resources.dll` beside `SW2URDF.dll`, keeping the `zh-TW`
subdirectory. The installer includes this file. Build/test from the repo root:

```powershell
./scripts/test_build.ps1
./scripts/test_i18n.ps1
python ./scripts/test_i18n_catalog.py
```

The runtime test checks the built satellite, language mapping and English
fallback under a non-English numeric culture, and verifies that nested labels
change while editable values and tree/combobox identities do not. The catalog
test checks all static captions in both export forms, dynamic unit resources,
case-insensitive duplicate keys and format placeholders.
